CHAPTER 01 // THE AVALANCHE EFFECT

The Avalanche Effect: How Single Bits Cascade Across Hash Space

A cryptographic hash takes input data of any arbitrary length and compresses it into a fixed-length hexadecimal digest. In a cryptographically sound hash function, mutating even a single bit cascades uncontrollably, flipping approximately half of all output bits.

The Strict Avalanche Criterion (SAC)

Formulated by Webster and Tavares in 1985, the Strict Avalanche Criterion mandates that whenever a single input bit is flipped, each of the output bits must change with a probability of 50%. This non-linear mathematical diffusion ensures that an adversary cannot correlate similarities between two plaintext messages based on similarities between their resulting digests.

CHAPTER 02 // MATHEMATICAL INVARIANTS

The Digital Fingerprint: Three Non-Negotiable Properties

A cryptographic hash function takes arbitrary input data and compresses it into a fixed-length hexadecimal digest. Unlike encryption, hashes are strictly one-way compression algorithms governed by three mathematical invariants.

Core Invariants of Cryptographic Hashing

To be classified as cryptographically secure, a hashing algorithm must uphold three mathematical properties:

sync_alt 1. Deterministic

The exact same input bytes will always produce the exact same fingerprint, regardless of machine architecture, operating system, or execution environment.

visibility_off 2. One-Way (Irreversible)

Given a digest $h$, finding the original message $m$ is computationally infeasible. There is no decryption key because hashing permanently compresses information.

shuffle 3. Collision Resistant

It is mathematically infeasible to generate two distinct inputs $m_1 \neq m_2$ that result in the identical hash output ($\text{hash}(m_1) = \text{hash}(m_2)$).

CRITICAL DISTINCTION: HASHING vs. ENCRYPTION

Hashing is a one-way mathematical function designed to verify data integrity without retaining the source contents. Encryption is a two-way transformation designed for confidentiality, allowing authorized holders of a secret key to decrypt and restore the original data.

CHAPTER 03 // ALGORITHM TAXONOMY & SECURITY

Algorithm Standards: Collision Resistance & Lifecycle Status

Not all hash functions remain cryptographically sound over time. As computational capacity surges and cryptanalysis matures, algorithms transition from standard-grade to deprecated or broken.

Cryptographic Hash Function Comparison

Modern systems rely on collision-resistant algorithms where finding two inputs with the same digest is mathematically infeasible:

SHA-256 RECOMMENDED
256-bit // 64 hex characters

Industry standard for file checksums, Git commit security, and blockchain architectures. Robust collision resistance.

NIST FIPS 180-4
SHA-512 RECOMMENDED
512-bit // 128 hex characters

High-capacity digest optimized for 64-bit processors. Ideal when extra collision margin is required.

NIST FIPS 180-4
SHA-1 DEPRECATED
160-bit // 40 hex characters

Theoretically and practically broken against collision attacks (SHAttered, 2017). Avoid for security-critical integrity.

RFC 3174 // LEGACY ONLY
MD5 BROKEN
128-bit // 32 hex characters

Severely vulnerable to collision forgery. Supported strictly for non-cryptographic file corruption checking.

RFC 1321 // NON-SECURITY
PASSWORD SECURITY WARNING: HASHES ARE TOO FAST FOR PASSWORDS

Never store user passwords as raw SHA-256 or MD5 hashes. Because cryptographic hashes are engineered to be computationally fast, an attacker with modern GPUs can test billions of guesses per second. Password storage requires intentionally slow, memory-hard key derivation functions like Argon2id, bcrypt, or PBKDF2.
