info What is a Hash?

A hash is like a fingerprint for data. Feed it any text or file, and it spits out a fixed-length string of letters and numbers. The same input always produces the exact same hash. Change even a single character of the input, and the hash comes out completely different. And it only works one way — you can't take a hash and reverse it back into the original data.

visibility Where You'll Actually See This
  • 1. Password storage — websites store a hash of your password, never the password itself.
  • 2. File downloads — publishers list a hash so you can confirm your download wasn't corrupted or tampered with.
  • 3. Git commits — every saved code change gets an ID that's a hash of that change's content.
  • 4. Docker images — container images have an ID that's a hash of everything inside them, so two people can confirm they have the exact same image.

Cryptography workspace

AES Studio

Everything happens locally inside your browser. Castle never stores or uploads your files, text, or passphrases.

Encryption vs Hashing

Hashing is one-way and verifies data has not changed. Encryption is two-way and keeps data secret from anyone without the key.

Why AES-256-GCM

AES is used by banks, cloud storage, hospitals, password managers, and secure messaging. GCM also detects changes.

Keys, salt, and IV

A passphrase is strengthened with PBKDF2 and a salt. A new IV ensures each encryption is unique.

Symmetric encryption

The same secret encrypts and decrypts. Never send it with the encrypted file.

Why encryption mode matters

ECB: the pattern remains visible.

GCM: encrypted data looks like noise.

Castle only lets you encrypt in GCM mode for this reason.
