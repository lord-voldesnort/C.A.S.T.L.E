WHAT IS ENCRYPTION?

FOUNDATIONS

At its foundation, encryption is a mathematical mechanism that scrambles human-readable or structured computer data into an unintelligible format that can only be restored to its original shape by possessing the corresponding cryptographic key.

01. INPUT draft

Plaintext

The original, unencrypted information in readable format (e.g., text, password, JSON, or binary file).

02. CONTROL key

Cryptographic Key

A sequence of pseudorandom bits required by the cryptographic cipher algorithm to transform and unlock data.

03. OUTPUT lock

Ciphertext

The randomized, unintelligible output generated by running plaintext through the cipher with the key.

WHY DOES ENCRYPTION MATTER?

THREAT MODELING

Without encryption, any network eavesdropper, malicious cloud administrator, or unauthorized actor with physical access to hard storage drives can view, exfiltrate, or alter sensitive systems. Encryption establishes zero-trust data confinement.

hard_drive

Confidential Storage

Protects sensitive files, local system documents, enterprise databases, and off-site cloud backups from direct extraction during drive loss or physical theft.

AT REST DEFENSE
lan

Private Communications

Powers TLS/HTTPS tunnels, VPN gateways, and peer-to-peer transmissions so intermediary ISPs and wiretaps observe only impenetrable cryptographic noise.

IN TRANSIT TUNNELS
vpn_key

Credentials & Secrets

Guards high-value authentication payloads, enterprise API keys, server certificates, and tokens against unauthorized internal inspections or log leaks.

CREDENTIAL VAULTING
share

Safe Data Sharing

Enables transmission of mission-critical files across untrusted cloud providers or public message queues without risk if the payload is intercepted.

EXPOSURE REDUCTION
warning
IMPORTANT LIMITATION: Encryption is a defensive primitive, not an entire security architecture. Encryption does not replace granular role-based access control, secure key management lifecycle policies, or disciplined endpoint hygiene.
03 //

MEET AES (ADVANCED ENCRYPTION STANDARD)

FIPS 197 SPECIFICATION

Standardized by the National Institute of Standards and Technology (NIST) in 2001 under FIPS 197 (originating as the Rijndael cipher), AES is the globally recognized gold standard for symmetric encryption.

AES is a symmetric-key block cipher. It divides plaintext into uniform chunks of exactly 128 bits (16 bytes) arranged in a 4×4 state matrix and iteratively scrambles them through a sequence of substitution, permutation, mixing, and key addition rounds.

priority_high CRITICAL ARCHITECTURAL DISTINCTION

The number in AES-128, AES-192, and AES-256 designates the KEY LENGTH in bits, not the block size. In all AES variants without exception, the block size is fixed at 128 bits.

SYMMETRIC ENCRYPTION: ONE SECRET KEY, TWO OPERATIONS

PARADIGM
lock

The Security Padlock Analogy

Think of symmetric encryption like a high-grade steel lockbox with a single physical key. The exact same physical key is required both to turn the tumbler clockwise to lock the box, and counter-clockwise to open it.

vpn_key 1 SECRET KEY = ENCRYPT + DECRYPT
OPERATION A: ENCRYPTION
Plaintext + Secret Key → Ciphertext
OPERATION B: DECRYPTION
Ciphertext + Same Secret Key → Plaintext
shield_lock THE KEY PROTECTION IMPERATIVE

An encrypted package is only as secure as the secrecy of the key. If an adversary steals the key, the encryption collapses completely. Never transmit the secret key across the same unsecured channel as the ciphertext.

WHY CASTLE USES AES-256-GCM (AUTHENTICATED ENCRYPTION)

NIST SP 800-38D

Standard encryption modes like CBC or ECB only provide confidentiality—they hide what the data says, but an adversary can still tamper with the ciphertext in transit (bit-flipping attacks). Castle uses Galois/Counter Mode (GCM), an authenticated encryption with associated data (AEAD) standard that guarantees the cryptographic triad.

TRIAD 01

visibility_off Confidentiality

Ciphertext hides the underlying message content from anyone who does not hold the cryptographic key.

TRIAD 02

verified Integrity

Guarantees that not a single bit of the encrypted payload was modified, altered, truncated, or corrupted in flight.

TRIAD 03

fingerprint Authenticity

Provides irrefutable mathematical proof that the payload was produced by a party in possession of the genuine secret key.

OUTPUT: Ciphertext + 128-bit Authentication Tag

RESULT: Authentic Plaintext (or immediate error rejection)
Nonce (Number used once):

A unique 12-byte initialization vector. Never reuse a nonce with the same key under AES-GCM.

Authentication Tag:

A 128-bit cryptographic seal. If even 1 bit of ciphertext is changed, tag verification fails instantly.

AAD (Associated Data):

Cleartext header info (e.g. packet IDs) bound to the tag for integrity without being encrypted.

ENCRYPTION IS NOT HASHING

CONCEPT COMPARISON

A frequent source of confusion in cybersecurity is conflating encryption with cryptographic hashing. While both process binary data through cryptographic math, they serve diametrically opposite roles in a secure architecture.

Property AES Encryption (e.g. AES-256-GCM) Cryptographic Hashing (e.g. SHA-256)
Main Purpose Confidentiality (hiding data while keeping it retrievable) Integrity & Digest Fingerprinting (verifying data hasn't altered)
Directionality Two-Way (Reversible with valid key) One-Way (Computationally irreversible)
Key Dependency Requires a secret key for encryption and decryption Requires no key (deterministic mathematical function)
Output Size Proportional to input size (+ Nonce and Tag metadata) Fixed length regardless of input (e.g., 256 bits / 32 bytes)
Typical Use Cases Encrypted communications, backup archives, credential lockers File checksums, Git commit IDs, password verification digests

IMPORTANT SECURITY LIMITATIONS

OPERATIONAL CAVEATS
gpp_maybe WHAT AES CANNOT DEFEND AGAINST
1. Plaintext RAM Exposure:

Data decrypted in RAM is readable by privileged system processes or kernel-level memory dumps.

2. Compromised Key Custody:

Anyone possessing or intercepting the secret key has full mathematical power to decrypt all corresponding ciphertext.

3. GCM Nonce Reuse Catastrophe:

Encrypting two different messages with the same key and same nonce completely breaks GCM integrity and leaks plaintext XOR diffs.

4. Host Malware & Spyware:

If the operating system hosting the browser or client is infected with keyloggers or screen grabbers, encryption cannot help.
